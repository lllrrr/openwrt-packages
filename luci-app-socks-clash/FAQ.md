## 安装相关

### Q1: 支持哪些 OpenWrt 版本？

**A:** SocksClash 支持 OpenWrt 21.02 及以上版本，推荐使用 OpenWrt 23.05+。

### Q2: 需要安装哪些依赖？

**A:** SocksClash 的依赖已在 Makefile 中定义：
- `luci-base` - LuCI 基础包
- `bash` - Bash shell
- `curl` - 网络下载工具
- `ca-bundle` - SSL 证书包

安装 IPK 时会自动安装依赖。

### Q3: 安装后找不到菜单入口？

**A:** 请尝试：
1. 清除浏览器缓存（Ctrl+Shift+Delete）
2. 重启 uhttpd 服务：`/etc/init.d/uhttpd restart`
3. 检查是否安装成功：`opkg list-installed | grep socks-clash`

### Q4: 如何卸载？

**A:** 
```bash
# 停止服务
/etc/init.d/socks-clash stop

# 卸载软件包
opkg remove luci-app-socks-clash

# 清理配置（可选）
rm -rf /etc/socks-clash
rm -rf /etc/config/socks-clash
```

## 配置相关

### Q5: 首次使用需要做什么？

**A:** 按以下步骤操作：
1. **下载内核**: 进入"设置"页面，点击"下载内核"
2. **添加订阅**: 进入"订阅"页面，添加订阅地址
3. **更新订阅**: 点击"更新所有订阅"
4. **启动服务**: 回到"概览"页面，点击"启动服务"

### Q6: 配置文件在哪里？

**A:** 
- **主配置**: `/etc/socks-clash/config/config.yaml`
- **订阅配置**: `/etc/socks-clash/config/*.yaml`
- **UCI 配置**: `/etc/config/socks-clash`

### Q7: 如何备份配置？

**A:** 
```bash
# 备份方法1：通过 LuCI
进入"编辑配置"页面 → 复制内容保存

# 备份方法2：命令行
tar -czf socks-clash-backup.tar.gz /etc/socks-clash /etc/config/socks-clash
```

### Q8: 配置文件损坏怎么办？

**A:** 
1. 停止服务：`/etc/init.d/socks-clash stop`
2. 删除损坏的配置：`rm /etc/socks-clash/config/config.yaml`
3. 重新生成配置：进入"概览"页面，点击"启动服务"（会自动生成）

## 订阅相关

### Q9: 支持哪些订阅格式？

**A:** 支持以下格式：
- Clash 订阅（推荐）
- Base64 编码的订阅（会自动解码）
- 标准 YAML 格式

### Q10: 订阅更新失败怎么办？

**A:** 检查以下几点：
1. **网络连接**: 确保路由器能访问订阅地址
2. **订阅地址**: 检查地址是否正确、是否过期
3. **DNS 解析**: 测试 `nslookup 订阅域名`
4. **日志查看**: 进入"日志"页面查看详细错误信息

### Q11: 订阅节点太多，如何过滤？

**A:** 使用订阅过滤器（v1.2.0 新功能）：
1. 进入"订阅"页面
2. 展开"订阅过滤器"部分
3. 设置：
   - **包含关键词**: 只保留名称包含这些关键词的节点（如：`香港|台湾|新加坡`）
   - **排除关键词**: 移除名称包含这些关键词的节点（如：`过期|剩余|官网`）
   - **节点类型**: 只保留选中类型的节点
   - **节点数量限制**: 限制最大节点数

### Q12: 订阅信息（流量、到期时间）在哪里看？

**A:** v1.2.0 版本会自动解析订阅商提供的 `Subscription-Userinfo` 头部信息，显示在订阅列表中。如果订阅商不提供此信息，则无法显示。

### Q13: 如何定时更新订阅？

**A:** 
1. 进入"订阅"页面
2. 启用"自动更新"
3. 设置"更新时间"（Cron 表达式）
4. 或进入"定时任务"页面统一配置

## 节点相关

### Q14: 如何手动添加节点？

**A:** 
1. 进入"服务器"页面
2. 点击页面底部的"添加"按钮
3. 选择协议类型（SS/VMess/VLESS/Trojan等）
4. 填写服务器信息
5. 点击"保存并应用"

### Q15: 如何测试节点延迟？

**A:** 
- **单个节点**: 在"服务器"页面，点击节点后面的"测试"按钮
- **批量测速**: 点击页面底部的"批量测速"按钮

延迟颜色说明：
- 🟢 绿色 (<150ms): 优秀
- 🟡 黄色 (150-400ms): 良好
- 🔴 红色 (>400ms): 较慢
- ⚠️ 红色 (超时): 无法连接

### Q16: 节点无法连接怎么办？

**A:** 
1. **检查节点信息**: 确认服务器地址、端口、密码等是否正确
2. **测速检查**: 使用测速功能检查节点是否可达
3. **防火墙**: 检查路由器防火墙是否阻止了出站连接
4. **日志查看**: 查看 Clash 日志了解详细错误

## 连接相关

### Q17: 代理地址是什么？

**A:** 默认代理地址（假设路由器 IP 为 192.168.1.1）：
- **HTTP 代理**: `http://192.168.1.1:7890`
- **SOCKS5 代理**: `socks5://192.168.1.1:7891`
- **混合代理**: `http://192.168.1.1:7893`（同时支持HTTP和SOCKS5）

### Q18: 如何在浏览器中使用代理？

**A:** 
**方法1**: 使用浏览器扩展（推荐）
- Chrome/Edge: 安装 SwitchyOmega
- Firefox: 安装 FoxyProxy
- 配置代理服务器地址

**方法2**: 系统代理
- Windows: 设置 → 网络和Internet → 代理
- macOS: 系统偏好设置 → 网络 → 高级 → 代理

详见"使用指南"页面。

### Q19: 为什么设置了代理还是无法访问？

**A:** 检查以下几点：
1. **服务状态**: 确认 SocksClash 服务正在运行
2. **节点选择**: 在"控制面板"中选择正确的节点
3. **模式设置**: 确认模式为"规则"或"全局"（不是"直连"）
4. **代理配置**: 确认客户端代理地址和端口正确
5. **网络连接**: 测试 `curl -x socks5://127.0.0.1:7891 https://www.google.com`

### Q20: Dashboard 一直显示"加载中"？

**A:** 
1. **检查服务**: 确认 Clash 服务正在运行
2. **等待启动**: 服务刚启动时需要等待几秒
3. **端口冲突**: 检查 9090 端口是否被占用
4. **浏览器**: 清除缓存或尝试无痕模式

## 性能相关

### Q21: 占用多少内存？

**A:** 
- **Clash Meta 内核**: 约 10-30 MB（取决于节点数量）
- **LuCI 应用**: < 1 MB
- **总计**: 通常 < 50 MB

### Q22: 对路由器性能要求高吗？

**A:** 
- **最低要求**: 64MB RAM, 单核 CPU
- **推荐配置**: 128MB+ RAM, 多核 CPU
- **注意**: 大量节点（>200）会增加内存占用

### Q23: 如何优化性能？

**A:** 
1. **减少节点**: 使用订阅过滤器，只保留常用节点
2. **关闭不用的端口**: 只启用需要的代理端口（HTTP/SOCKS5）
3. **定期重启**: 设置定时重启清理连接（每周一次）
4. **日志级别**: 设置为 `warning` 或 `error`

## 故障排查

### Q24: 服务无法启动？

**A:** 按以下步骤排查：
1. **检查内核**: 确认已下载 Clash 内核
   ```bash
   ls -la /etc/socks-clash/core/clash
   ```
2. **检查配置**: 验证配置文件
   ```bash
   /etc/socks-clash/core/clash -t -d /etc/socks-clash/config
   ```
3. **查看日志**: 
   ```bash
   cat /tmp/socks-clash.log
   logread | grep clash
   ```
4. **手动启动**: 测试是否能手动启动
   ```bash
   /etc/socks-clash/core/clash -d /etc/socks-clash/config
   ```

### Q25: 服务启动后无法访问外网？

**A:** 
1. **检查节点**: 确认已选择正确的节点
2. **测试连接**: 
   ```bash
   curl -x socks5://127.0.0.1:7891 https://www.google.com
   ```
3. **检查规则**: 查看"控制面板"中的连接记录
4. **检查端口**: 确认端口监听正常
   ```bash
   netstat -tulpn | grep clash
   ```

### Q26: 更新内核后无法启动？

**A:** 
1. **恢复备份**: 如果有备份的内核
   ```bash
   cp /etc/socks-clash/core/clash.bak /etc/socks-clash/core/clash
   chmod 755 /etc/socks-clash/core/clash
   ```
2. **重新下载**: 进入"设置"页面，强制重新下载
3. **手动下载**: 从 [mihomo releases](https://github.com/MetaCubeX/mihomo/releases) 下载对应架构的文件

### Q27: 配置更新后不生效？

**A:** 
1. **重启服务**: 进入"概览"页面，点击"重启服务"
2. **检查配置**: 确认修改已保存
3. **生成配置**: 如果使用订阅，重新生成配置文件

## 对比说明

### Q28: SocksClash 和 OpenClash 有什么区别？

**A:** 

| 特性 | SocksClash | OpenClash |
|------|-----------|-----------|
| **定位** | 专注代理 | 全功能透明代理 |
| **透明代理** | ❌ 不支持 | ✅ 支持 TUN/REDIRECT |
| **DNS 劫持** | ❌ 不支持 | ✅ 支持 FakeIP |
| **路由表** | ❌ 不修改 | ✅ 策略路由 |
| **防火墙** | ❌ 不修改 | ✅ 自动规则 |
| **配置复杂度** | 🟢 简单 | 🟡 复杂 |
| **内存占用** | 🟢 较低 | 🟡 较高 |
| **适用场景** | 手动配置代理 | 全局透明代理 |

**选择建议**:
- **选 SocksClash**: 只想为特定应用配置代理
- **选 OpenClash**: 需要全局透明代理、DNS分流

### Q29: 为什么不支持透明代理？

**A:** 这是设计决策：
1. **简化配置**: 避免复杂的网络配置
2. **减少风险**: 不修改路由表和防火墙
3. **灵活控制**: 用户可以自主选择哪些应用使用代理
4. **降低门槛**: 更容易理解和排查问题

### Q30: SocksClash 是 OpenClash 的精简版吗？

**A:** 不完全是。SocksClash 是一个**独立项目**：
- **参考**: 借鉴了 OpenClash 的订阅管理和日志系统
- **定位不同**: 专注于代理功能，不是简单的精简
- **代码独立**: 完全重写，代码结构不同
- **目标用户**: 不需要透明代理的用户

## 进阶使用

### Q31: 如何自定义规则？

**A:** 
1. 进入"规则"页面
2. 添加自定义规则
3. 支持的规则类型：
   - `DOMAIN-SUFFIX` - 域名后缀匹配
   - `DOMAIN-KEYWORD` - 域名关键词匹配
   - `GEOIP` - IP 地理位置匹配
   - `IP-CIDR` - IP 地址段匹配

### Q32: 如何使用不同的代理组？

**A:** 
v1.2.0 自动生成以下代理组：
- **🚀 PROXY**: 手动选择节点
- **♻️ AUTO**: 自动选择最快节点
- **🔄 FALLBACK**: 故障转移
- **🎯 DIRECT**: 直连
- **🛑 REJECT**: 拒绝连接

在"控制面板"中可以切换。

### Q33: 如何查看实时连接？

**A:** 
进入"控制面板"页面，可以看到：
- 实时上传/下载速度
- 当前连接数
- 每个连接的详细信息（目标地址、使用的节点）

### Q34: 支持IPv6吗？

**A:** 
Clash Meta 内核支持 IPv6，但默认禁用。
如需启用：进入"设置"页面，勾选"启用 IPv6"。
