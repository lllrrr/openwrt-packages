代理节点

每个 worker 对应一个 PassWall 节点，测速时经该节点探测候选 Cloudflare IP。 「IP 列表」留空使用第一个启用的列表；填写「DDNS 域名」的 worker 只把最优 IP 写到 Cloudflare DNS， 留空则照旧写回 PassWall 节点。没有 worker 时使用下面的「单节点测速」。

在线 CM 源 IP 列表

仅在「IP 来源 = 在线 CM 源」时使用。五个列表共享在线源地址，各自按端口和国家码过滤； 节点可在「节点」页指派其中一个列表，未指派的节点使用第一个启用的列表。 端口只用于挑选候选 IP，实际探测仍走节点自己的端口。 延迟上限填 0 表示跟随「设置」页的全局值；不同地区标准不同（如港日 120ms、美欧 300ms）， 可给每个列表单独设置，所属节点的探测只按该列表的上限筛选。

启用名称国家码（不勾选 = 全部）端口延迟上限 (ms)

候选 IP 来源

内置文件为 CIDR 段：默认每个 /24 随机取一个地址；IPv6 每个 /64 取一个样本。在线源格式为 IP:PORT#国家码。

延迟筛选与探测

任意一次探测失败该 IP 立即丢弃，只有全部探测都成功才保留。并发上限 0 表示全部节点同时运行。延迟是经节点 SOCKS 测得的全链路耗时，包含节点自身 RTT；远端节点常超过 200ms，延迟上限默认不限（0），调得太低会把所有候选全部丢弃。

真实下载实测

所有 worker 停止延迟探测后，逐节点串行下载：只测每个节点延迟最优的前 N 个 IP；5 秒内不足 1 MB 的候选会被 curl 快速中止并判失败。下载失败的行会被剔除；全部失败时保留延迟排序。

限时迭代

每个节点独立循环：第一遍测初始候选，之后每遍只复测上一遍通过的 IP，直到时长结束或候选收敛到 ≤「迭代收敛阈值」（默认 5，最多 100）。该阈值与下载测速候选数相互独立；迭代期间不写结果，结束后统一导出并对最终候选做下载实测。

定时任务

显示与本程序相关的 cron 任务（当前用户的 crontab 可直接修改，/etc/crontab 中的条目只读）。所有任务都是普通 crontab 行，可改计划、类型、节点或启停；没有单独的主任务。

DDNS（Cloudflare 优选 IP）

每个节点在「节点」页填写自己的 DDNS 域名；留空的节点只测速，不写 DNS。 写入的是该节点本次最优的 IP（IPv4 → A，IPv6 → AAAA）。Zone ID / 名称都留空时按域名自动查找。 API Token 需要该 Zone 的 DNS:Edit 权限。启用橙云代理后 Cloudflare 会返回自己的 边缘 IP，写入的优选 IP 不会生效，优选场景请保持关闭。
