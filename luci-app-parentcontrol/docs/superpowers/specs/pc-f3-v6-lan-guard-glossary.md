# pc-f3-v6-lan-guard · Glossary（白话词典）

> 目的：上一版 spec 术语太重，这份是**给非专业读者**的对照表。所有词都用"能干什么"来解释，不用更专业的词解释专业词。
> 角色产出：**conductor**（阶段 2）。code/review/test 只读不改。

## 一、这份任务在说什么（一句话）

路由器上有个「家长控制」功能。**IPv4 那张拦截表的第一条是"放行家里内网"，IPv6 那张表忘了写这一条。** 结果：孩子设备被封锁时，IPv4 还能连家里设备，IPv6 连不上。本次任务就是把 IPv6 缺的那条补上。

## 二、词表

| 术语 | 白话解释 |
|---|---|
| **IPv4 / IPv6** | 两套互联网地址体系。同一个"局域网"在两套体系里各有一份地址。**两条路都得能通，功能才算完整。** |
| **局域网（LAN）** | 你家里的内网。路由器是它的中心。家里设备互相通信、连路由器管理页，都走局域网。 |
| **内网 / 外网** | 内网 = 家里；外网 = 互联网。家长控制要管的是**外网**。 |
| **封 锁 / 拦截** | 到点或超额度时，路由器丢弃该设备的某些数据包，让目标网站打不开。 |
| **丢弃（DROP）** | 数据包被直接扔掉，不分给任何人。设备那头表现为"连不上/一直转圈"。 |
| **放行（RETURN）** | 数据包不再被这张表处理，交给后面正常流程走。设备那头表现为"正常能用"。 |
| **守 卫** | 放在拦截表**最前面**的那条"放行"规则。作用是：**先给内网和管理入口开一道门，防止家长控制把自己（或家里的东西）也一起锁死。** |
| **链（chain）** | 内核里一串规则的名字。好比一张"检查清单"，数据包从上往下逐条比对。 |
| **配额链 `PARENTCONTROL_QUOTA`** | 本功能用来做"到点/超量就断网"的检查清单。守卫就放在这张清单的最前面。 |
| **mangle PREROUTING** | 数据包刚进路由器、还没决定往哪送的那个时刻。本功能的检查清单挂在这里，所以**内网互相通信也会被它看到**。 |
| **直连路由 / on-link（我简称"直连"）** | "这个网段就在我这块网卡上，不用经过任何别的路由器"。**只有直连的网段才是"家里"。** |
| **` via `（经由此处）** | 路由表里"去某个网段要经过某台路由器"的意思。**带 ` via ` 的都不是直连，必须排除**，否则会把整条互联网都当成"家里"放行。 |
| **G UA（全局地址）** | 运营商分配的公网级 IPv6 地址。**会变**（运营商定期换）。 |
| **U LA（内部地址）** | 家庭内部自用的 IPv6 地址，不会暴露到公网。**相对稳定**。 |
| **link-local（`fe80::`）** | 只在同一根网线上有效、出了这个网段就没用的地址。属于"家里"。 |
| **族 / 族感知** | 族 = IPv4 还是 IPv6。族感知 = 同一段代码**先分清自己在处理哪一套，再用对应的数据**，别拿 IPv4 的数据去填 IPv6 的表。 |
| **降级（graceful degradation）** | 家里没有 IPv6 时，**不报错、不生成多余的规则**，其它功能照常。 |
| **幂等（idempotent）** | 同样的事做一遍和做十遍，结果一样（不会越做越多、越做越乱）。本功能每分钟跑一次，必须幂等。 |
| **指纹 `quotaspec`** | 上次生成的规则内容存成一份文本。这次生成的和存的一样 → **一个字都不动内核**（省事、也避免抖动）。 |
| **tick（每分钟那一拍）** | 本功能由定时任务每分钟唤醒一次，重新评估要不要改规则。 |
| **收尾 gate（收尾检查）** | 测完/部署完，逐项核对"真机是否回到干净状态"的检查表（配置没被改、规则条数对得上、iPad 没受影响……）。 |
| **A/B 对照** | 加规则前记一次、加规则后记一次，用数字差证明"确实生效了"。 |
| **变异测试（mutation）** | 故意把代码改坏一处，看测试**会不会报警**。报警 = 测试有效；不报警 = 这条测试是摆设。 |
| **白盒 / 黑盒** | 白盒 = 不碰真机、在本地用假的路由器跑测试；黑盒 = 在真路由器上真跑一遍。 |

## 三、本次修复到底改了什么（白话）

1. 新加一个"查家里有哪些 IPv6 网段"的小函数（读 `ip -6 route`，只取直连、排除带 ` via ` 的行）。
2. 原来那个"放行内网"的函数只会用 IPv4 网段；改成**先看自己是在处理哪一套地址，再用那套的网段**。
3. 把新查出来的 IPv6 网段也写成"放行"规则，插到 IPv6 配额链最前面。
4. 相应地，测试用的"假 `ip` 命令"也要学会回答"IPv6 路由"这个新问题。
5. 版本号 1.8.1 → 1.8.2。

## 四、不做什么（白话）

- **不动 IPv4 现在的任何规则**（现状是基线，逐字节都不能变）。
- **不新增任何"新品种"的规则或表**（不加 ipset、不加 nft、不改防火墙结构）——这是你之前定的硬规矩"不要擅自添加路由表之类的东西"。
- **不动路由器上的网络/防火墙/passwall/Clash 配置**。
- **不修**那个"发往路由器的 DNS 查询会被"放行内网"一起放过"的**老现象**——IPv4 一直这样，IPv6 本次也保持一致；要改得单独立项。
