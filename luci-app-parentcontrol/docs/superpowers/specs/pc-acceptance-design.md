# pc-acceptance — 需求与验收标准（design / spec）

> ⚠ **已脱敏**：本文档由 conductor 做了凭据/隐私脱敏（路由器口令 → `[REDACTED]`，真机 IP/MAC → 占位符），
> 因为该仓库 origin 是公开仓库且目录在同步盘内。真机真实值只在 conductor 的 handoff 消息里下发，**不落盘进仓库**。

> 用途：本项目**唯一的验收标准清单**（A1..A46）。黑盒/白盒/回归用例都必须能回溯到这里的编号。
> 来源：README（= 本项目对外承诺的 spec）+ 代码（`root/etc/init.d/parentcontrol`、`root/usr/lib/parentcontrol/common.sh`、`luasrc/`）。

## 0. 背景与边界

- 项目：OpenWrt/LuCI 家长控制插件。**按网址/域名过滤某台设备** + **可用时段 + 每日累计使用额度**。
- 明确 out of scope：UI 上的「时间限制」「协议过滤」两页（已移除，但 shell 侧仍需兼容执行存量条目）；QUIC/HTTP3 的 SNI；自带 HTTPDNS 的 App 的解析式覆盖；寒暑假无全国数据源（只手动区间）。
- 真机参考环境：ImmortalWrt 23.05 x86/64，iptables-legacy 1.8.8（**无 `addrtype`**），LuCI + ucode。

## A. 需求域 1：部署与生命周期（含旧版缺陷修复）

| ID | 验收标准（可观测判据） |
|----|------------------------|
| **A1** | **ash 兼容**：所有 shell 脚本在 busybox ash 下**不因 bash-only 语法中止**（典型：`local Z1,Z2,...=0`、`10#`）；`start` 能跑到底，time 之后 protocol/weburl 两组规则**确实被安装**。 |
| **A2** | **旧规则清理**：`del_rule` 用正确的变量/表清掉旧链与跳转；反复 `start` 不会**堆叠**规则（链存在时先 flush）。 |
| **A3** | **陈旧锁**：脚本被中断留下锁文件后，后续 `start()` 不再 exit 1（能自愈）；`start()` 用 `trap` 保证中途失败也**清掉锁文件**。 |
| **A4** | **hotplug iface**：`/etc/hotplug.d/iface/97-parentcontrol` 的启用判断正确；接口事件后**真的重装规则**（不是恒假直接 exit 0）。 |
| **A5** | **启用开关**：`basic.enabled=0` → **一条 PARENTCONTROL 规则都不建**（mangle/filter 都没有）。 |

## B. 需求域 2：拦截位置 + flow offloading

| ID | 验收标准 |
|----|----------|
| **A6** | **挂载点 = mangle PREROUTING**（不是 OUTPUT）：只有这里同时看得到客户端源 MAC 与明文负载，且在 flowtable/DNAT 之前；`-m mac --mac-source` 在此处有效。 |
| **A7** | **有受管设备（列表里存在，不论是否勾选）→ 停用 flow offloading**：移除 fw4 的 `... flow add @ft` 规则，并用 conntrack 清掉受管设备现有连接（`conntrack` 缺失则跳过清理但不报错）。 |
| **A8** | **停用插件 → 恢复 flow offloading**（把 `flow add @ft` 规则装回）。 |
| **A9** | **两条链 + 顺序**：`PARENTCONTROL_QUOTA`(封锁) 与 `PARENTCONTROL_ACCT`(计数) 都在 mangle，PREROUTING 顺序 **QUOTA → ACCT**（被封的包不再进计数链）；每额度条目一条空链 `PCA_<module>_<idx>`。 |

## C. 需求域 3：域名/CIDR 过滤 + IP 解析刷新

| ID | 验收标准 |
|----|----------|
| **A10** | **目标生成**：条目目标 = 「解析出的目标 IP」+「明文串（DNS 53 / TLS SNI 80,443）」两类规则；**封锁与计数共用同一生成器**（枚举集合永不漂移）。 |
| **A11** | **CIDR 直通**：`domains` 里**含 `/` 的项直接当 CIDR 封，不做解析**（应急口子）。 |
| **A12** | **IPv4 粒度**：默认封 `/24`（`basic.ip_mask` 可改 `32`）；IPv6 封 `/64`。 |
| **A13** | **解析累积只增不减**：结果按条目存 `/etc/parentcontrol/ips/weburl_<N>`，CDN 换节点后老节点仍被挡；**条目删除时清理对应文件**。 |
| **A14** | **刷新**：cron 按 `basic.ip_refresh` 分钟（`0`=关闭，不写 cron）调用 `refresh_ip`；crontab 条目由插件自己维护。 |
| **A15** | **名称解析**：不填域名时靠关键词猜（`关键词` → `.com`/`www.`/`.cn`）；解析同时取 apex 与 `www.` 变体。 |

## D. 需求域 4：每日额度 / 可用时段 / 双档案 / 共享池（核心）

| ID | 验收标准 |
|----|----------|
| **A16** | **计时口径 = 条目自己规则命中的流量**：机器(time)条目=该设备全部；协议条目=该设备该端口/协议；网址条目=该设备发往该条目目标的流量（目标 IP + 明文 DNS/SNI）。 |
| **A17** | **三态**：① 时段外 → 封（且这段流量**不计入额度**）；② 时段内未用完 → 放行；③ 耗尽 → 封（不论在不在时段内，**立即切断**）。 |
| **A18** | **全禁 = 额度填 0**（判据 `封 = 不在时段内 或 已用 ≥ 额度`，N=0 第二项恒成立）；勾 **不限额度** → 只受时段约束且**不消耗共享池**。 |
| **A19** | **可用时段**：每档案一对 `sd/hd_qstart|qend`，`HH:MM:SS` 秒级，默认 `00:00:00-23:59:59`（全天）；**不跨日、起必须早于止**；脏数据（起≥止/非法）按「不限制」兜底。 |
| **A20** | **时段按 UTC+8 换算**：交给 `-m time`（默认按 UTC 解释）的区间是 UTC；**改路由器系统时区不影响**判定；时段外区间用**正向区间**表达（本机 iptables 拒绝 `! -m time`），跨 UTC 零点切两段。 |
| **A21** | **额度按自然日、0 点重置、不结转**（用量文件按 `YYYYMMDD`）。 |
| **A22** | **采样**：cron 每分钟采样字节增量；**有流量且增量 ≥ `basic.usage_min_kb`（默认 8 KB）才记 1 分钟**；同一分钟只记一次；**首次采样（无 base）按「自规则建立以来」计一次**。 |
| **A23** | **共享额度池**：同名并入（也可不填自己额度、完全交给池）；组内流量加总、共用额度；**池耗尽 → 所有成员一起封**；「挂了池但池没额度」→ 用条目自己的额度/用量（分支键是「池里确实有额度」而非「挂了池」）。 |
| **A24** | **双档案**：平日/节假日各自独立的时段+额度；按当天类型取 `sd_*`/`hd_*`。 |
| **A25** | **无额度/未勾不限 = 不限（fail-open）**：额度为空但未勾「不限额度」→ 按不限处理（防静默全禁）；要全禁必须显式填 0。 |
| **A26** | **池内条目额度归一**：非纯数字（空/`abc`/`-1`/`+5`/` 5`）一律归 0；迁移与运行**共用同一归一器**。 |

## E. 需求域 5：防自锁

| ID | 验收标准 |
|----|----------|
| **A27** | `PARENTCONTROL_QUOTA` 链**最前面**永远有「目标为局域网网段（含路由器自身 IP）→ RETURN」的放行规则；即使无设备条件的条目耗尽，**SSH/LuCI 仍可连**。 |
| **A28** | 拿不到局域网网段时，**对「无设备条件（没填 MAC/IP）」的条目不封锁**，只记日志（宁可少封不错封）。 |
| **A29** | `pc_lan_nets` 从 `network.*` 的 `proto=static` 段取 `ipaddr/netmask`；无配置返回空。 |

## F. 需求域 6：设备身份（防改 MAC）

| ID | 验收标准 |
|----|----------|
| **A30** | 设备条件 = **MAC 与静态 IP/主机名任一命中即生效**（`add_dev_rules` 各出一条规则）；计数侧为避免双计只出一条（`ip` 优先）。 |

## G. 需求域 7：节假日 / 寒暑假 / 时间口径

| ID | 验收标准 |
|----|----------|
| **A31** | **法定节假日自动识别**：有网时拉当年+次年（jsDelivr 主 / raw 备）；成功后 **7 天内不重拉**；缓存缺失先用包内 bundle 兜底、bundle 也缺才联网；抓取失败**不改动**已有文件；无数据**降级**周五晚?→周中/周末判定（周六周日=节假日）。 |
| **A32** | **寒暑假手动区间**：`MM-DD` 每年重复 或 `YYYY-MM-DD` 绝对日期；支持跨年区间；缺字段的坏行被跳过。 |
| **A33** | **优先级**：寒暑假 > 法定节假日/调休 > 周末/工作日。 |
| **A34** | **时间口径**：日子类型与额度一律按 **UTC+8**，与路由器系统时区无关。 |

## H. 需求域 8：界面 + 统计

| ID | 验收标准 |
|----|----------|
| **A35** | **列表摘要**：`开启/备注/设备/静态IP/域名IP/档案/今日额度/重置`；设备列 `MAC（设备名）`；档案列紧凑摘要（两档案相同只写一次；全天时段不写、秒不写）；今日额度 `12 / 30 分钟`、勾不限显示`不限`、条目不存在显示`-`；每行「编辑」。 |
| **A36** | **独立编辑页**（`weburl_edit`）容纳全部详细字段；起/止校验「起必须早于止」（不得出现自己和自己比的 bug）；`domains` 说明含 CIDR。 |
| **A37** | **「使用限额」页**：共享额度池 + 寒暑假区间可增删改。 |
| **A38** | **文案中文字面量**（不受 LuCI 界面语言影响）；菜单/页面缓存问题有说明（`/tmp/luci-indexcache*`）。 |
| **A39** | **使用统计页**渲染：今日进度、最近 30 天趋势、按条目/设备、重置记录；数据源 `stats_tsv` 的列**只允许 `tsv.lua` 解析**（历史上多份按下标解析导致整列静默错值）。 |
| **A40** | **已移除页面**：界面无「时间限制」「协议过滤」入口；但 shell 侧**仍执行启用中的 time/protocol 条目**。 |

## I. 需求域 9：迁移 / 向后兼容

| ID | 验收标准 |
|----|----------|
| **A41** | 老「时段」模式 → **不限额度 + 可用时段 `09:00:00-21:00:00`**（旧语义补集跨日无法无损换算）。 |
| **A42** | 老「每日额度」模式 → 额度保留、**时段保持不设（全天可用）**（不得静默收紧）。 |
| **A43** | 老「关闭」→ 不限额度（全天可用）。 |
| **A44** | 老额度为「空/0/负数/非数字」→ 按老判据视为**不限额度**并**强制改写 `unlimited=1`**（否则会把"不限"翻成全天全禁）。 |
| **A45** | 已经是新模型的条目**一个字段都不动**；每个老字段只翻译一次（`mode` 等翻完即删）。 |
| **A46** | 迁移前**自动备份**到 `/etc/parentcontrol/backup/parentcontrol.<时间戳>.bak`；迁移对**配置幂等**（重复执行无新变化；每次会另存备份属预期）。 |
